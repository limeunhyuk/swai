# 컴공으로 살아남기 · 중간 발표 프로토타입

HTML·CSS·JavaScript와 사전 작성 콘텐츠로 구성한다. DB·AI 추천 엔진·자동 크롤러는 추가하지 않는다. 기존 [공개 사이트](https://savecs.netlify.app/)와 GitHub–Netlify 배포를 유지한다.

## 실행

`start.cmd` 또는 `npm run dev` → http://127.0.0.1:4173/ . Node.js가 필요하다. 종료는 Ctrl+C.

## 현재 범위 — 콘텐츠 2026-11-02.5

- 홈: 이력서 즉시 확인 / 3학년 시작하기. 버튼마다 짧은 설명.
- 즉시 확인: 입력 없이 네 학기 로딩(학기당 0.6초·총 약 2.4초, 동작 줄이기 설정 시 단축) 후 김컴공 예시 이력서·진로·실제 공고. 세 예시만 순환하며 실제 게임 완료로 기록하지 않는다.
- 실제 게임: 성·이름만 선택 입력. 빈 칸만 김/컴공으로 보충. 3-1~4-2의 진로 1개+일상 1개씩 총 8선택.
- 진로: 3-1 프로젝트/자격증/인턴 준비 → 3-2 해당 준비의 사건 → 4-1 유지 또는 변경 → 4-2 마무리. 최종 추천은 4-1의 마지막 방향, 이전 경험은 보존한다. 자격증은 정보처리기사/SQLD/빅데이터분석기사 준비를 고르며 취득으로 기록하지 않는다.
- 스탯: 공부 네 항목은 각 가로 5칸×세로 2줄, 생활 세 항목은 세로 배치. 효과 순합 +2·개별 ±2 이내, 0~10 경계에서 실제 변화량 표시.
- 학점: 3.50/4.3 시작, 두 선택 후 룰렛 0.9초 자동 실행. 다음 학기 버튼은 유지. 중간 하락을 허용하는 전반적 상승 시연값이며 결과에는 2학년~4-2 선 그래프.
- 결과: 실제 선택 경험·구체 직무와 취업 분야·공고·피드백을 구분하고 다시 하기 강조. 즉시 보기 하단은 이름 설정부터 실제 게임으로 이동.
- 추천: 프로젝트→서비스 통합 엔지니어/대기업 SI·IT 서비스, 자격증→정보시스템 운영 엔지니어/공기업·공공기관 전산직, 인턴→AI 에이전트 엔지니어/IT 서비스·플랫폼 기업. 실제 자격·합격 예측이 아닌 진로 예시다.
- 모집: 각 경로 두 개씩 총 여섯 실제 공고. 카드 전체를 누르면 원문 새 탭으로 직행. [출처](JOBS.md).
- 의견·이메일 모두 선택. 하나 이상 입력하면 제출 가능, 실제 저장 응답 뒤에만 입력 초기화.

## 기록·분석

브라우저 → Netlify 함수 → 기존 Apps Script GET/JSONP insert → 기존 tab_master/tab_final. Google 로그인·새 탭·새 비밀키가 필요하지 않다. `.env`는 Git 제외하고 배포 환경변수 APPS_SCRIPT_URL을 유지한다. [저장 설정](SETUP.md).

새 익명 ID는 보안 난수 12자리이며 기존 ID는 유지한다. Netlify context.ip와 첫 페이지 document.referrer를 수집한다. 방문·게임 시작/첫 선택/완주·즉시 보기 시작/예시 도달·원문 클릭과 피드백을 기록한다. [시트 열 확장](SHEETS.md)을 완료하고 형식 3을 활성화했다. 새 행의 landingUrl은 진입 주소, advice는 의견 본문만 남기고 추적 정보는 추가 열로 분리한다. 기존 URL/JSON 행은 보존하며 혼합 분석을 지원한다. 실제 지원 완료는 추적하지 않는다. 자동 재전송은 하지 않고 분석에서 ID 중복 제거한다.

`node scripts/summarize-legacy.mjs tab_master.csv tab_final.csv`로 두 탭 CSV를 분석한다. 출처·플랫폼·게시판·게시일별로 묶으며 각 수준의 고유 브라우저를 다시 중복 제거한다. 예시 도달·예시 공고 클릭은 게임 시작 없이도 집계하고 게임 완주와 구분한다. 테스트는 제외하며 시트 전체 행 수를 방문 수로 세지 않는다. 시트 내 자동 집계 탭은 추가하지 않았다.

## 홍보 링크

`/d1`, `/f1`, `/e1`, `/a1`, `/k1` 같은 주소에서 같은 홈을 제공한다. 시트 UTM은 dc/fm/ev/ar/ka, 별도 홍보코드는 게시물별로 구분한다. 기존 `/c1`은 `/k1`과 같은 코드로 연결하며 `/r/e01` 등과 utm/utm_source도 유지한다. 짧은 경로가 쿼리보다 우선하며 미등록 코드는 unregistered로 분류한다. 전달된 링크는 원래 배포 코드로 집계된다.

[PROMOTION.md](PROMOTION.md)에 15개 후보+카카오톡과 기존 예약 코드를 정리했다. 실제 게시 이력은 아니다. 카카오톡 대화방 이름은 미지정이다. 새 글에는 새 코드를 예약하고, 실제 게시 후 한국 날짜·시각·원문 주소를 등록한다. 기존 글 수정은 같은 링크를 쓴다. 등록 변경은 commit/push해 반영한다.

예약: `node scripts/add-campaign.mjs d5 dcinside web-game - - 2`

게시 후: `node scripts/add-campaign.mjs d1 dcinside web-game YYYYMMDD HHmm 1 https://홍보글주소`

## 검증

기본 게임 검사는 **대표 경로 9개+예시 3개**로 제한한다. 세 시작 방향에서 세 최종 방향으로 유지/변경하는 사례, 방향 변경 직후 피드백·경험 보존·학점·스탯 경계·중복 반영을 확인한다. 과거의 2,187회 조합 반복은 기본 검사에서 제거했다. 전수·대량 검사는 사용자의 별도 명시 승인 없이 추가/실행하지 않는다.

변경에 관련된 검사만 1회 실행한다. 통과한 동일 검사를 수정 없이 다시 돌리거나, 가벼운 UI 변경에 전체 검사·반복 브라우저 완주를 붙이지 않는다. 사용자 ‘다음 창 정리’에는 검사·배포를 추가하지 않는다. 이번 재발 방지 수정은 `node scripts/check-game.mjs`의 대표 검사 1회만 확인했다. 세부 운영 제한은 SWAI 루트 AGENTS.md를 따른다.

기록 유효성·기존 저장 형식·출처 고정·예시/게임 분리·플랫폼별 중복 제거·짧은 링크 대응·홍보 코드 등록/동결/관리표를 검사한다. 코드 등록 검사는 임시 폴더에서 수행해 실제 홍보 대응표를 바꾸지 않는다. 실제 수요나 추천 효과의 검증 결과가 아니다.
