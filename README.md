# 컴공으로 살아남기 · 프로토타입 v0.2

HTML·CSS·JavaScript와 사전 작성 콘텐츠로 구성한 중간 발표용 체험이다. 별도 프레임워크·DB·AI 추천 엔진은 사용하지 않는다.

## 로컬 실행

`start.cmd`를 열거나 이 폴더에서 `npm run dev`를 실행하고 `http://127.0.0.1:4173/`에 접속한다. Node.js가 필요하다. 종료는 서버 창에서 `Ctrl+C`.

## 구현 범위

- 성·이름 각각 입력, 흐린 기본값 ‘김’·‘컴공’. 빈 칸만 기본값으로 보충한다. 성별만 필수이며 MBTI 입력은 제거했다.
- 3학년 1학기부터 네 학기. 학기마다 진로 사건 하나와 일상 사건 두 개, 총 열두 번 선택한다.
- 진로 4개·일상 12개의 사전 작성 사건과 48개 선택지. 연애·조별과제·알바·친구·생활 상황을 포함하고 학기별 일상 목록에서 중복 없이 두 개를 뽑는다.
- 일곱 스탯의 선택 효과는 순합 +2, 개별 변화 ±2 이내로 맞췄다. 선택 전 ↑/↑↑·↓/↓↓로 크기를 표시한다. 0~10 경계에서는 실제 변화량이 줄어들 수 있다.
- 학기 말 학점 룰렛 네 번. 초기 누적 3.5/4.5에서 학업·탐구 스탯을 소폭 반영해 오르내리며 전반적으로 상승한다.
- 이름·최종 학점·실제 선택으로 얻은 인턴/프로젝트 등의 경험을 담은 웹 이력서. 경험 선택 시 사전 작성 한 줄을 기록하고, 2학년 말~4-2의 누적 학점을 단순한 선 그래프로 보여준다.
- 소프트웨어·플랫폼 개발 / 데이터·AI / 클라우드·인프라 계열을 작게, AI 에이전트 / AI 평가·실험 / AI 인프라 자동화 엔지니어 직무를 크게 표시한다. 결과 도달 시 브라우저에 다음 묶음 순서만 기억한다. 세 묶음을 모두 보면 처음부터 반복한다.
- 계열별 실제 공고 두 개, 총 여섯 개를 원문에서 수집해 사전 저장했다. 모집 상세·원문 링크·확인일·마감 정보를 표시하고 상세 클릭을 기록한다. 출처·조건·갱신 방법은 [JOBS.md](JOBS.md)에 있다.
- 의견·선택 이메일 입력. 의견만·이메일만·둘 다 제출 가능하고 모두 비면 제출하지 않는다. 실제 저장 응답이 확인돼야 성공 표시·입력 초기화를 한다.

게임 진행과 캐릭터 이름은 페이지 메모리에만 있다. 익명 브라우저 ID와 추천 순서만 localStorage에 둔다. 저장소가 막혀도 현재 페이지에서는 진행한다.

## 실제 통계 연결

브라우저 → Netlify 함수 → 기존 Apps Script → Google Sheets로 저장한다. 기존 배포의 로그인 없는 GET/JSONP insert를 재사용한다. 2026-11-02 GitHub main 업로드·Netlify 환경변수 설정·재배포를 완료했다. [실제 사이트](https://savecs.netlify.app/)에서 기록 설정 활성화와 이메일만 입력한 피드백의 저장 성공·입력 초기화를 확인했다. 미연결·저장 응답 미확인을 성공으로 표시하지 않는다.

기존 `project_임시`의 `tab_master`·`tab_final` 열을 유지하며, 출처는 utm, 단계별 세부는 landingUrl·advice의 구조화된 값으로 남긴다. 새 Google 로그인·탭·스크립트 배포는 필요 없다. 자세한 저장 형식과 집계는 [SETUP.md](SETUP.md)에 있다. 기존 원자료를 읽거나 삭제한 것은 아니다.

홍보 링크 예: `/?utm=everytime-yonsei`. 방문 때 정한 출처를 방문·시작·첫 선택·완료·모집 클릭·피드백에 연결한다. 로컬 또는 `?test=1`은 테스트로 표시한다. Google 시트의 새 자동 집계 탭은 아직 없으며, 기존 두 탭을 CSV로 내보내 `node scripts/summarize-legacy.mjs tab_master.csv tab_final.csv`로 테스트 제외·중복 제거한 출처별 통계를 계산한다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `public/content.json` | 프로필·스탯·사건 목록·선택·경험·추천 진로·실제 공고 스냅샷 |
| `public/game.js` | 사건 구성·선택 효과·학기 전환·시연 학점 |
| `public/app.js` | 시작·플레이·룰렛·이력서·모집 상세·피드백 화면 |
| `public/tracking.js` | 익명 ID·방문 출처·기록 전송·추천 순서 저장 도우미 |
| `netlify/functions/record.mjs` | 입력 검사·Apps Script 전달·실제 저장 응답 확인 |
| `scripts/summary.mjs` | 출처별 집계 규칙. Google 코드 수정 없이 로컬 분석에서 사용 |
| `scripts/summarize-legacy.mjs` | 기존 두 시트의 CSV로 실제 출처별 통계 계산 |
| `scripts/serve.mjs` | 로컬 정적 파일·동일 기록 함수 제공. 선택적으로 `.env` 로드 |

공개 저장소에 `.env`·비밀값을 포함하지 않는다. Netlify 공개 폴더는 `public`, 함수 폴더는 `netlify/functions`다.

## 검증

`npm test`는 모든 1,296가지 사건 구성과 성별/선택/룰렛 경계 12경로의 1,308회 완주, 선택 보상 균형·±2 제한·3.5 시작과 상승/하락·공고 메타데이터·스탯 한계·이름 기본값·룰렛 중복 방지·선택한 경험만 기록하는 동작을 검사한다. 모든 선택 조합을 전수 검사하는 것은 아니다.

저장 입력·이메일 선택·서버 미연결/실패·응답 ID, 브라우저의 출처 고정·저장소 차단, 기존 형식 복원·CSV 읽기·브라우저/기록 중복·단계 연결·테스트 제외·피드백 구분도 검사한다. 기존 API에서는 자동 재전송을 하지 않고 실제 저장소의 중복 방지가 아닌 분석 시 ID 중복 제거를 사용한다. 실제 외부 연결 점검은 테스트 두 행의 성공 응답으로 확인했으며 원자료 행을 독립적으로 다시 읽어 검증한 것은 아니다.

실제 참가자의 재미·수요·진로 탐색 효과를 검증한 결과는 아니다. 현재 구현 상태와 브라우저 QA 결과는 상위 `project/md/06-아이디어구체화.md`·`07-중간구현기획.md`에 유지한다.
